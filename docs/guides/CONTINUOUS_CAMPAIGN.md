# 連續戰役：第一卷七章

本版將原本單場斷橋展示接入既有 `CampaignState`、`RefitCamp`、`Roster` 與 `CampaignLedger`。畫面保留目前的人物外形、肖像、移動朝向、相機平滑、MSAA 與 VSync。

## 遊玩流程

主選單選「開始新戰役」或「繼續戰役」。新戰役需確認，既有存檔會先備份成 `campaign.previous.json`。

每章依序為劇情／決策 → 整補與戰前軍議 → 戰鬥或談判 → 已保存的戰後行軍帳 → 下一章。決策確定後會立即存檔，不能透過反覆選擇領取補給。

| 章 | 劇情與玩法 |
|---|---|
| 1 斷橋初筆 | 接受投降或追擊；擊潰敵軍，建立第一筆戰果 |
| 2 殲滅的筆跡 | 掩護傷員：保護後衛 35 秒；追擊：擊潰敵軍、額外補給 |
| 3 初次無戰 | 第 1 章接受投降且獲勝、第 2 章救援且獲勝，可談判直接通行；否則強攻 |
| 4 神像流淚 | 花費補給護送並保護 45 秒，或徵糧後交戰 |
| 5 同盟誓約 | 分擔軍糧或獨自突破；盟約選擇影響下一章的敘事 |
| 6 叛將之筆 | 安置盟軍或追責背誓者，承接同盟記錄 |
| 7 神話改寫 | 逐一記名或留下傳奇；完成後呈現七章決策與損失 |

第二、四章的保護對象若已陣亡，會明確改用最後一支生還部隊。對象潰逃或全滅即失敗；我方將軍衛隊全滅仍優先判敗。撤退會保存本章失利與已發生的傷亡。

## 傷亡與存檔

- 兵力與既有傷兵池逐章延續，醫治每人消耗 1 補給；永久陣亡不可醫治。
- 全滅小隊移出常備軍，具名隊長留在永久名冊。招募採持久序號，避免重新使用陣亡者身分。
- 全滅隊伍先前留在營中的舊傷兵，轉交新的傷員接收軍官；原兵種、模板能力和紀念遺物保留，舊隊長不復活。
- 下一章地方補給為 8。可戰兵力低於 24 時，登記一支全新的 24 人地方預備隊；不復活原編制。
- 結算、決策、整補與前進採完整檢查點保存。寫檔成功才更新記憶體狀態；失敗顯示錯誤並提供重試。
- 存檔位於執行檔資產資料夾旁的 `saves/campaign.json`。戰鬥中關閉，重開從該場戰前檢查點接續，未提供任意戰中快照。
- 驗證模式使用獨立 `verification-saves`，不碰正常玩家存檔。

## 建置與驗證

需要 C++20 編譯器、CMake、現有 GLFW/ImGui 依賴。建置目標 `DuanqiaoPlayable`、`CampaignFlowTest`、`CampaignMissionTest`，並將 `assets` 放在執行檔旁。

`CampaignFlowTest` 驗證兩條第三章路線、七章終態、真實損失吸收、重載、重複結算拒絕、壞檔和寫檔失敗保留原檔。`CampaignMissionTest` 驗證保護計時、潰逃／陣亡失敗、無殲滅勝利、撤退與終態不可覆寫。

`DuanqiaoPlayable --campaign-check`、`--campaign-combat-check` 擷取完整介面與章節流程，使用明確標記的腳本戰果，並在章節間重新讀回存檔。`--visual-check` 讓首戰自然進行，記錄幀時間與截圖。

加入 `--campaign-natural-check` 可讓全卷由原有教令與戰鬥模擬自然結算，驗證模式於戰前使用可用補給醫治傷兵；和 `--campaign-combat-check` 合用可測強攻路線。第四至六章會縮小至 960×640 檢查介面，終章恢復 1440×810。

此七章是可持續擴充的第一卷。完整十五章歷史時代、治理系統、神話實體與地形改寫、最終四聲部結局仍屬後續擴充，不能把本卷摘要當作全部需求已完成。
