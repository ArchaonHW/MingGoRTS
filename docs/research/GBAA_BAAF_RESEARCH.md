## 🎯 白皮書定位

- **提出者**:全球區塊鏈會計聯合會(GBAA)——民間專業聯合組織,非聯合國或其附屬機構,不代表任何準則制定機構立場。
- **核心框架**:區塊鏈會計查證框架 **BAAF**(Blockchain Accounting Attestation Framework)。
- **設計宣稱**:依循聯合國 UNCTAD-ISAR 會計與報告準則工作框架,對接 IFRS 永續揭露準則(S1/S2)與國際確信準則 ISSA 5000。
- **核心主張**:台灣具備高密度會計專業人口與完整上市櫃永續揭露制度,有條件在 **2028 年前**建立亞太第一個區塊鏈會計查證參照標準——「標準由此地制定,查證由市場執行,結果向國際揭露框架對接」。
- **市場背景**:永續揭露從自願走向強制,資本市場對非財務數據的要求已從「有揭露」進化為「可查證」。

## ⚠️ 三個結構性缺口

| 缺口 | 內容 |
|------|------|
| 查證量能不足 | 主管機關永續發展路徑圖已將全體上市櫃公司納入溫室氣體盤查與確信時程,但確信量能高度集中於大型會計師事務所;中小企業、單一活動與專案層級的碳數據幾乎沒有可負擔的查證服務 |
| 數據可信度缺口 | 現行永續數據多以問卷自評、試算表傳遞與事後補登產生,缺乏可追溯的產生軌跡;揭露量增加而可信度未同步提升,放大漂綠風險 |
| RWA 會計真空 | 實體資產代幣化(RWA)快速發展,但代幣化資產如何入帳、鏈上憑證如何存證、相關揭露由誰查證,國際間尚無一致準則;會計基礎設施缺位使機構資金無法進場 |

## 🌐 國際框架對接

BAAF 不另創準則,而是把既有國際框架串接成可執行的查證鏈條——這是框架能被快速採用、也能對外互認的關鍵設計。

| 國際框架 | 性質 | 在 BAAF 中的角色 |
|----------|------|------------------|
| UNCTAD-ISAR(聯合國貿易和發展會議・國際會計和報告準則政府間專家工作組) | 企業會計與 SDG 揭露之政府間指引 | 規劃對接之基準框架:核心 SDG 指標(GCI)作為企業層級揭露基線 |
| IFRS S1 / S2(ISSB) | 一般永續揭露與氣候相關揭露準則 | 揭露端出口:查證後數據直接支援 S1/S2 報導 |
| ISSA 5000 | 永續確信之國際準則 | 查證層方法論依據,確保會計師執行之專業一致性 |
| GHG Protocol | 溫室氣體量測與邊界規範 | 碳數據之量測邊界與計算基準 |

> 注意:白皮書明載上述對接均屬**規劃性質**,非正式背書。

## 🏛️ BAAF 三層架構

核心設計原則:**「標準輕、網絡重」**——聯合會只擁有標準與登錄簿,數據存證交給自動化系統,查證交給市場上既有的會計專業。組織極輕,網絡極大。

| 層級 | 名稱 | 職責 |
|------|------|------|
| **L1** | 數據存證層(Data Anchoring) | 來源數據於產生當下計算雜湊值上鏈,附時間戳與產生軌跡,形成不可竄改的證據鏈;全程自動化,不依賴人工作業 |
| **L2** | 專業查證層(Professional Attestation) | 由完成 GBAA 登錄之執業會計師,依 ISSA 5000 方法論對存證數據執行查證;聯合會不自建查證人力,採授權與登錄制,直接運用台灣既有會計專業量能 |
| **L3** | 標準認可層(Registry & Recognition) | 聯合會維護查證標準、登錄查證結果、發布年度基準報告;登錄簿是整個框架的公信力所在——企業引用、投資人查閱、國際互認都以登錄簿為準 |

## 🔄 查證流程與各方分工

對企業而言流程只有五步;對聯合會而言,人力只介入標準與登錄兩端。

```
① 需求登錄          ② 數據上鏈           ③ 會計師查證      ④ 結果登錄         ⑤ 揭露引用
企業提交查證申請  →  自動存證·雜湊·時間戳  →  依 ISSA 5000 執行  →  載入 GBAA 登錄簿  →  支援 IFRS S1/S2 報導
```

| 參與方 | 負責環節 | 取得 |
|--------|----------|------|
| 企業 | 提交數據、配合查證 | 可查證數據與登錄編號,供揭露與融資引用 |
| 登錄會計師 | 執行查證(②→③) | 依委任契約收取查證公費 |
| 技術夥伴 | 存證系統運維 | 依服務契約計價 |
| GBAA 聯合會 | 標準維護、資格登錄、結果登錄 | 登錄與年度基準報告之公信力中樞 |

## 🎪 適用場景

1. **活動型碳數據鏈**:將媒體曝光、活動參與、社區能源、地方生態、資源循環串成同一套可追溯數據,使單一活動的碳排放首次成為可查證、可揭露的資產。
2. **供應鏈金流 × 碳流整合查證**:交易金流與碳流數據同源存證,讓「每一筆錢對應多少碳」成為可驗證的敘述,直接服務範疇三盤查與供應商管理。
3. **RWA 代幣化資產之會計處理**:代幣化資產的入帳、存證與揭露依 BAAF 執行查證,補上機構參與 RWA 市場前最缺的會計信任層。
4. **永續報告書確信之前置數據治理**:報告書確信之前,先以 BAAF 完成數據層查證,降低確信成本與重編風險。

## 🗺️ 三階段路徑

| 階段 | 時程 | 關鍵成果 |
|------|------|----------|
| Phase 1 框架奠基 | 2026 | 白皮書雙語發布;查證標準第一版;完成 3–5 件示範查證案並載入登錄簿 |
| Phase 2 網絡擴張 | 2027 | 會計師登錄制度全面運作;查證登錄簿線上公開;與國內會計專業團體及學研機構建立合作;啟動一項國際組織對話關係 |
| Phase 3 亞太參照 | 2028 | 啟動跨境互認試點(新加坡、香港或日本擇一);發布首份《亞太區塊鏈會計查證基準報告》 |

三階段共用同一個槓桿:**標準與登錄簿的先發位置**。查證案例每累積一件,登錄簿的參照價值就增加一分;後進者引用標準,即是為台灣位置背書。

## 🤝 治理模式

聯合會採**專案責任制**:權益來自帶案、做案、整案三種具體貢獻與對應責任,一切合作於專案執行前書面確認。

- **企業**:提出查證需求,取得登錄編號與可揭露數據
- **執業會計師**:完成登錄後承接查證委任,依 ISSA 5000 執行
- **技術與研究夥伴**:依個案參與存證系統、方法論與基準研究
- **政策與國際夥伴**:受邀參與標準諮詢與年度基準報告發布

免責聲明重點:白皮書為框架性文件;查證服務均依個案委任契約辦理;涉及會計師法定業務者悉由執業會計師依法辦理。

## 💡 對 MingGoRTS 的啟發

BAAF 的核心結構與本專案既有的帳本/存證系統高度同構,可作為設計語言與機制參照:

| BAAF 概念 | MingGoRTS 對應系統 | 可借鑑點 |
|-----------|--------------------|----------|
| L1 數據存證(雜湊+時間戳+產生軌跡) | `Ledger`/`LedgerChain` 雜湊鏈帳簿、`BattleRecorder` rootHash 完整性驗證 | 「產生當下即存證」已是現行設計;可補強產生軌跡(provenance)欄位,記錄資料由哪個系統/哪一 tick 產生 |
| L2 專業查證(第三方依方法論驗證) | `HistorianReport` 查帳段 | 可引入「查證者角色」概念——史官不只是記錄者,也是對帳簿執行方法論(抽驗、複算)的查證者,呼應 ISSA 5000 式確信流程 |
| L3 登錄簿公信力(可查閱的登錄編號) | `potato.ledger_chain/1` 存檔格式 | 每筆已查證帳簿可配發「登錄編號」供外部引用(戰報、成就、社群查驗),把 rootHash 包裝成玩家可分享/可查驗的證明 |
| 「標準輕、網絡重」 | 引擎只定義 schema(`potato.*`),產生與驗證交由各玩法系統 | 維持 schema 極簡、驗證邏輯下放——與目前 assets schema 分層策略一致 |
| 金流 × 碳流同源存證 | 複式記帳五帳戶 | 遊戲內可類推「資源流 × 事件流」同源記帳:每筆資源異動強制綁定觸發事件,讓「每一點資源對應哪次行動」可驗證 |

**實務可採項目(優先度排序)**:

1. **登錄編號機制**:為已結算戰役帳簿產生短碼登錄 ID(由 rootHash 派生),讓玩家能貼出可驗證的戰績證明。
2. **產生軌跡欄位**:在 `LedgerChain` entry 增加 `provenance`(系統來源、tick、觸發事件 id),對齊 BAAF L1「產生軌跡」概念。
3. **查證式史官**:`HistorianReport` 查帳段擴充為「確信報告」——抽驗 N 筆分錄重算餘額、驗證雜湊鏈連續性,輸出查證結論而非僅列帳。
