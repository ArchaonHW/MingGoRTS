# 2026-10-02　本機建置與遊戲執行問題紀錄

## 主要結論

這次最主要的問題是 **GitHub `main` 的 README 描述了尚未出現在該分支的遊戲內容**。本機 `feature/iris` 與遠端 `main` 都位於 `d6929904`，所以並不是單純漏下載更新，而是文件與分支內的程式版本不一致。

在 `main` 衍生的副本建置完整引擎時，另外遇到真實的 MSVC 原始碼編譯錯誤。改用含有可玩遊戲的 `feat/game-backend-services`，在另一份獨立副本中建置 `DuanqiaoPlayable` 後，成功啟動並完成一場戰鬥。這證明本機能以 MSVC 建置及執行這個可玩版本；不代表原本 `main` 的錯誤已被修正。

## 目的與處理範圍

目的是確認作者的專案能在這台電腦修改、編譯與執行。考量 Windows Sandbox 每次關閉後會清除環境，本次使用本機測試副本，保留工具與下載的依賴。

測試副本可避免測試修改混入共同編輯的原始碼，但不是執行隔離環境。此次沒有切換、合併、提交或推送原工作目錄的 Git 分支，也沒有修改共同編輯的原始碼。

## 處理過程

1. **檢查原始專案及環境。** 確認是 C++20 / CMake 專案。一般終端找不到 CMake 與 MSVC，但後續找到已安裝的 Visual Studio 2022 及其內附工具，不必重新安裝。原有 MinGW 是 GCC 6.3，無法滿足此專案的 C++20 需求，本次改用 MSVC。
2. **建立第一份本機測試副本。** 複製程式及文件，排除 Git 歷史、代理設定和舊建置輸出；新增檔案放在原專案忽略的 `Temp/` 內。
3. **先驗證最小修改與執行。** `MinimalTest` 只使用向量運算標頭，因此另建專用 CMake 入口，避免為最小測試下載整個引擎的依賴。載入 `vcvars64.bat` 並使用 Ninja 後建置成功。曾將副本向量 z 從 3 改為 4，重建後輸出從 `Length: 3.74166` 變成 `Length: 4.58258`；再恢復原值並重建，檔案雜湊與原始檔一致。
4. **嘗試原分支的完整建置。** 補齊依賴後，CMake 設定與產生建置檔成功，但完整引擎被 `SecuritySystem` 編譯錯誤擋住，IDE GUI 也被 AI 相依模組的編譯錯誤擋住。數學測試及獨立 AI 測試套件則能執行，AI 測試顯示 7／7 通過。
5. **核對 GitHub 分支。** 唯讀查詢 GitHub 分支版本，確認本機 `feature/iris` 與遠端 `main` 是同一個 commit。再查看其他分支，找到 `feat/game-backend-services` 內有 `Gameplay/`、`Campaign/`、`assets/` 與 `DuanqiaoPlayable` 建置目標。
6. **建立第二份可玩版本副本。** 用 `git archive` 匯出 `feat/game-backend-services` 的精確版本，不切換原工作目錄。沿用先前下載的 GLFW，補齊與該分支記錄一致的 ImGui，使用分支內已生成的 GLAD。
7. **建置並執行遊戲。** `DuanqiaoPlayable` 及所需模組編譯成功。第一次連結時 manifest 工具遇到短暫檔案占用，重試成功，無須修改程式碼。實際開啟遊戲視窗、按下「開戰」，確認單位移動、兵力／士氣與戰況更新，最後進入「勝利」結算。

## 分支狀態與共同編輯的注意事項

本次檢查時，本機工作分支為 `feature/iris`，基底為 `d6929904`，與 GitHub `main` 相同。沒有找到本機 `feature/iris-ui` 或 `feature/map-system`；使用者提到的分支結構不能直接視為已建立。

Git 分支是版本指標，不是會自動繼承其他功能分支內容的資料夾。只從目前 `main` 建立自己的分支，仍不會包含 `feat/game-backend-services` 的可玩程式。若要在自己的分支修改此遊戲，後續需選定正確基底，或透過審閱過的合併帶入；本次未執行這些操作。

第二份副本是檔案快照，不帶 Git 歷史。副本中的修改不會自動回到 `feature/iris`，也不會自動同步到 GitHub。
