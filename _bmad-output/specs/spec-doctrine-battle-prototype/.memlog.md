- (direction) Source: brainstorming-session-2026-09-16 斷橋原型規格 + 工作樹已存在的 Gameplay/ 實作（BattleController/Doctrine/FlowField/Squad + DoctrineBattleDemo）；本 spec 為實作補回合約
- (decision) 玩家動詞是「寫 doctrine」不是「打」：FF12 Gambit 語義——規則依 priority 排序取第一條命中，規則數即指令槽消耗
- (capability) CAP-1 部署階段為每支小隊編寫 priority 排序 doctrine 規則集（trigger+action+threshold+priority），命中即執行，無命中墊底 HoldPosition
- (capability) CAP-2 即時層自動執行：每 0.25s 遊戲時間重建 SquadContext（血量/士氣/敵距/受擊/眾寡/友軍接戰/到點）並評估 doctrine 下達 SquadOrder
- (capability) CAP-3 CP 介入：玩家耗 Command Point 對單隊做限時命令覆寫（holdSeconds 後恢復 doctrine 控制），CP 不足或階段不對回 false
- (capability) CAP-4 小隊戰鬥模擬：成員數即戰力，傷亡按比例扣士氣，士氣歸零 routing 潰逃不受控，未接戰時士氣自回
- (capability) CAP-5 squad 級 flow field 尋路：反向 Dijkstra integration field，支援障礙與地形成本，全隊共用場查詢 O(1)
- (capability) CAP-6 三階段循環 Deployment→Execution→Resolution 與勝負判定（全殲/擊潰=Victory，反之 Defeat，逾時上限收 Draw）
- (capability) CAP-7 戰鬥事件以 std::function callback 輸出（doctrine 命中/潰逃/勝負），不依賴 EventBus，上層自接
- (constraint) Gameplay 層自含無外部依賴、無 EventBus 硬綁定；小隊為最小可控單位（無個體 agent 尋路）——契合引擎無 navmesh 現況
- (constraint) MSVC 與 MinGW 皆須編譯；無新第三方依賴；無 banned C functions；不碰 external/、build/
- (constraint) Headless 可驗證：DoctrineBattleDemo 為 CLI 含 assertions 且註冊進 ctest（POTATO_TESTS）
- (constraint) doctrine 評估節流 0.25s/次（DOCTRINE_INTERVAL）——效能與「腳本執行感」的平衡，非每幀評估
- (decision) 故意不做（二期彈藥）：大地圖、外交、養成、多將內鬥、連鎖時間軸、敵方學習、沙盤模擬器、數值成長、情報點經濟、斷後回合、永久死亡名冊、戰鬥 UI
- (assumption) 士氣採每小隊獨立制（brainstorm open question「全軍共用 vs 每隊」原型選每隊，保留局部潰敗戲劇性，待實測）
- (assumption) 敵我同構：敵方用同一套 DoctrineSet 機制，人格/簽名習慣由規則內容表達而非專用 AI
- (question) 指令槽上限（4 vs 5）與「槽位債」超載延遲——原型程式碼無槽位強制，僅以規則數隱含消耗
- (question) doctrine 規則是否需冷卻狀態防卡循環——原型靠 priority+墊底規則，未實作冷卻
- (note) 工作樹隨同的引擎層改動（Physics/Rendering/Scene 修正、MathUtils/Frustum.h、Physics/CollisionDetection.h、PhysicsTest/MathTest 擴充）屬並行強化，不屬本 spec 合約
- (note) 詞彙量漂移：brainstorm 最小詞彙為 觸發器x5/條件x4/動作x8/槽=4；實作為 8 triggers/6 actions，條件併入 trigger+threshold，槽位無強制
