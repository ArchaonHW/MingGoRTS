# MingGoRTS 專案脈絡

_此檔案包含AI代理實施代碼時必須遵循的關鍵規則和模式。專注於代理可能錯過的非顯著細節。_

---

## 技術堆疊

### 核心引擎
- **Unreal Engine 5.7** - 使用最新版本功能，Nanite支援大規模單位渲染
- **C++ 模組化架構** - Runtime 模組系統，熱路徑用C++，其餘用Blueprint
- **Blueprint 混合開發** - C++核心邏輯 + Blueprint快速原型，GameplayTags優於自定義事件

### 插件架構
- **MingCore** - 事件總線和核心服務，實施事件優先級隊列
- **MingStrategic** - 戰略地圖層
- **MingTactical** - 戰術戰鬥層，預分配記憶體池
- **MingPersonal** - 個人角色層
- **MingBuilding** - 基地建設層
- **插件版本兼容性檢查** - 確保跨插件序列化一致性

### AI資產管道
- **Stable Diffusion** - 民國風格2D美術生成，API變更風險管理
- **AIVA API** - 歷史風格背景音樂，品質控制平衡
- **自動化工作流** - 資產生成→導入→品控

### 關鍵技術決策
- **事件驅動優化** - MingCore事件總線必須批處理1000+單位戰術數據
- **記憶體管理** - 二進制戰術數據格式 + 預分配記憶體池
- **性能優先** - 60fps目標驅動所有架構決策
- **跨平台支援** - Windows/Android/iOS，移動端性能挑戰需特別關注


## 關鍵實施規則

### 語言特定規則
- **C++熱路徑優化**：性能關鍵代碼用C++，避免熱路徑記憶體分配
- **Blueprint快速原型**：非關鍵邏輯用Blueprint快速迭代
- **GameplayTags優先**：單位狀態用GameplayTags系統，不使用自定義事件
- **避免Tick()濫用**：用事件驅動更新代替每幀檢查
- **組件模式優先**：優先使用UE5組件系統而非深度繼承

### 框架特定規則
- **事件驅動通訊**：所有插件間通訊通過MingCore事件總線
- **插件版本兼容性**：實施插件間版本檢查機制
- **分層數據持久化**：每層獨立存儲，通過事件同步
- **配置驅動設計**：所有數值用DataAsset，避免硬編碼
- **跨平台適配**：自動適應輸入方式和性能優化

### 測試規則
- **100%測試通過**：所有測試必須通過才能標記任務完成
- **性能基準測試**：每Sprint必須通過60fps + 1000+單位測試
- **插件集成測試**：確保層次間通訊和版本兼容性
- **負載測試**：模擬1000+單位AI決策和記憶體壓力
- **事件追蹤測試**：監控事件總線延遲和瓶頸
- **跨平台自動化**：Windows/Android/iOS兼容性驗證

### 代碼品質與風格規則
- **UE5命名約定**：類別PascalCase，函數PascalCase，變數camelCase
- **插件模組前綴**：所有插件用Ming前綴（MingCore、MingTactical等）
- **文檔化要求**：所有公開API用Doxygen格式註釋
- **記憶體安全**：預分配記憶體池，避免熱路徑分配
- **性能優先**：每個決策必須考慮60fps目標影響

### 開發工作流規則
- **Git分支策略**：feature/epic-X用於特定史詩功能
- **代碼審查重點**：檢查插件兼容性、性能影響、UE版本風險
- **持續整合**：自動編譯測試和平台打包
- **AI資產管道**：自動化資產生成→導入→品控流程

### 關鍵不要錯過規則
- **60fps不可協商**：所有架構決策必須服從性能目標
- **記憶體預分配**：戰術層必須使用記憶體池，避免熱路徑分配
- **事件批處理**：MingCore必須實施事件優先級隊列處理1000+單位
- **插件兼容性**：每個插件必須檢查版本兼容性
- **避免Tick()依賴**：用事件驅動代替每幀更新
- **原型優先驗證**：複雜功能先用簡單幾何體驗證性能
- **歷史決策真實性**：所有決策後果必須基於歷史文獻驗證
- **跨平台性能挑戰**：移動端1000+單位需要專門優化
